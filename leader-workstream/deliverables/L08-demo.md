## Objetivo y alcance

Probar un guion repetible que conecte emisor, API y aplicación. La ejecución requiere el encargo técnico correspondiente.

Participan simulación, Mauricio y la PWA desplegada en el entorno autorizado. Validación técnica y presentación son pruebas distintas.

**Dependencias.** L04 y L07 verificados para el recorrido mínimo. L05/L06 solo para ampliaciones verificadas. Simulador, equipo y entorno acordados.

## Secuencia

Fijar revisiones; preparar inicio, lectura y hora; ejecutar simulado, cortar emisor y API por separado y recuperar; ajustar el guion a capacidades verificadas. Acordar fallback de presentación.

## Contratos y datos

Muestra rastreable con ID, hora, unidad, calidad y procedencia. Datos de demo ficticios. Guion identifica capacidades realmente demostradas. Consulta [integración](../INTEGRATION_PLAN.md).

## Comportamiento y excepciones

Mostrar montaje inicial, vacío o fallo si ocurre, distinguir nodo offline y API caída. Usar evidencia capturada como respaldo identificado, sin presentarla como transmisión en vivo.

## Aceptación, pruebas y evidencias

Ensayar en equipo y navegador objetivo con comandos existentes autorizados. Registrar revisiones, tiempo, pasos, resultados, limitaciones y evidencia sanitizada. Usa los comandos reales del proyecto y registra skips con motivo. La aceptación exige evidencia de cada comportamiento aplicable y pruebas esenciales satisfactorias.

## Condiciones de bloqueo

Recorrido de API sin verificar, entorno indisponible, credencial expuesta o demostración que atribuye capacidades no probadas. Registra evidencia, responsable y condición concreta de reanudación. Continúa solo en trabajo independiente autorizado.
